# genie-web

English | [简体中文](./README.zh-CN.md)

Visual inspiration and the mesh-warp algorithm are based on Chad Etzel’s [MeshWarpEffect](https://github.com/jazzychad/MeshWarpEffect) — a macOS Genie Effect recreated with a deformable mesh. `genie-web` brings that technique to the modern web using WebGL. Special thanks to the original author for sharing it.

```bash
npm i genie-web
# bun add genie-web
```

A unified configuration schema shared seamlessly across Vanilla JavaScript, React, Vue, and Svelte.

This library warps a **snapshot** of `target`. It does not manage windows: no dialog lifecycle, no stacking policy, no cache invalidation for changing UI. Static nodes work with defaults. Live windows need you to own snapshot timing, `z-index`, and what happens to the real DOM after `hide()`.

> [!NOTE]
> Note: This port was generated by an LLM.

## Required vs. Optional Options

**Vanilla (`createGenie`) — Required**

| Field | Type | Description |
| --- | --- | --- |
| `target` | `string \| HTMLElement` | The target element to animate. Accepts a CSS selector or a DOM node. |
| `origin` | See below | The anchor point where the element shrinks into or expands from. |

**Framework Components — Required**

| Field | Type | Description |
| --- | --- | --- |
| `open` | `boolean` | Visibility state. `true` expands the element (warp in), `false` minimizes it to the anchor (warp out). |
| `origin` | See below | The anchor point (same as Vanilla). The component animates its root/child container. |

All other options are optional. Default values are listed in the table below.

`origin` accepts:

- A CSS selector string (`"#dock-icon"`)
- An `Element` node
- A `DOMRect` instance
- Viewport pixel coordinates `{ left, top, width, height }`

## Configuration

Pass these in `createGenie({ … })`, update them via `genie.set({ … })`, or provide them via the `config` prop on React / Vue / Svelte components. The Svelte action also accepts these properties alongside `open` and `origin` in a flat object.

| Name | Required | Default | Type | Description |
| --- | --- | --- | --- | --- |
| `duration` | No | `680` | `number` | Animation duration in milliseconds. |
| `direction` | No | `"auto"` | `"auto" \| "top" \| "right" \| "bottom" \| "left"` | The edge of `target` where the funnel connects. `"auto"` picks the edge from `origin` vs `target`; or lock to `"top"`, `"right"`, `"bottom"`, or `"left"`. |
| `slideEnd` | No | `0.5` | `number` (`0–1`) | When near-edge pinching finishes. Smaller values close the funnel mouth earlier. |
| `translateStart` | No | `0.38` | `number` (`0–1`) | When the whole mesh starts sliding toward `origin`. Overlaps the pinch. |
| `easing` | No | `"linear"` | `"linear" \| "easeOut" \| "easeInOut"` | Easing of the **timeline** (progress 0 → 1). Not the funnel shape. |
| `curve` | No | `"inOut"` | `"inOut" \| "in" \| "out" \| "linear"` | Easing of the **funnel side walls**. Independent of `easing`. |
| `columns` | No | `20` | `number` | Horizontal mesh subdivisions. Higher is smoother and heavier. |
| `rows` | No | `48` | `number` | Vertical mesh subdivisions. |
| `fadeStart` | No | `0.88` | `number` (`0–1`) | When the mesh starts fading (mostly at the end of hide). |
| `zIndex` | No | `2147483000` | `number` | Overlay canvas `z-index`. Default sits above almost everything; lower it if the origin icon must stay on top. |
| `wireframe` | No | `false` | `boolean` | Draw the mesh as a wireframe. |
| `reducedMotion` | No | `"auto"` | `boolean \| "auto"` | `"auto"` honors `prefers-reduced-motion`; `true` skips the warp; `false` always plays. |
| `snapshot` | No | `"fresh"` | `"fresh" \| "last"` | `"fresh"` recaptures every show/hide. `"last"` reuses the previous successful bitmap (falls back to fresh if none). Also overridable per call: `show({ snapshot: "last" })`. |
| `capture` | No | Built-in | `fn` or `{ take, clone? }` | **Replaces** both built-in snapshot paths. See [Custom `capture`](#custom-capture). |
| `open` | No (Vanilla only) | Inferred from CSS | `boolean` | Initial visibility for `createGenie`. Frameworks use the `open` prop. |

`direction` examples:

```js
{ direction: "auto" }    // Inferred from relative geometry
{ direction: "bottom" }  // macOS Dock: funnel downward
{ direction: "top" }     // Funnel upward
{ direction: "left" }    // Funnel to the left
{ direction: "right" }   // Funnel to the right
```

### Timing: `easing` vs `curve`

Two different knobs, despite similar names:

```
progress  0 ──────── slideEnd ────────────── 1
          [ pinch the mouth →              ]

               translateStart ────────────── 1
               [ slide the mesh toward origin ]

easing  = how fast that progress clock runs
curve   = how the funnel side walls bend while pinching
```

`wireframe: true` is the practical way to see what you changed. There is no in-repo playground for these fields.

## Snapshot lifecycle

The warp textures a WebGL mesh with a **bitmap of `target`**, not the live DOM.

- **Static node, default snapshot:** no extra setup. The built-in path is enough.
- **Changing UI (`<dialog>`, lazy images, lists that swap preview):** you own cache, warmup, and invalidation. The library will not notice that the next hide is a different picture.

What actually happens:

1. `show()` / `hide()` capture **then** set `target` to `visibility: hidden`.
2. After **`show()`** finishes, visibility is restored.
3. After **`hide()`** finishes, `target` **stays hidden** until the next `show()` completes (or `destroy()`). That is intentional for a closed window. Miss it, and it looks like “the animation ended and the node vanished”.
4. Built-in **`hide()` recapture is always the SVG clone**, even if `show()` used HTML-in-Canvas. Those two bitmaps can differ. Use `hide({ snapshot: "last" })` to warp the same texture you just showed.

### Built-in paths (only when `capture` is omitted)

1. **HTML-in-Canvas** (if the browser exposes it) — experimental [HTML-in-Canvas](https://github.com/WICG/html-in-canvas) (`layoutsubtree`, `drawElementImage` / `texElementImage2D`). Faster and closer to real paint. It may **temporarily relocate the live node** into a canvas (placeholder left behind). Do not copy that pattern in custom `capture`.
2. **SVG clone** — used when HTML-in-Canvas is missing, fails, or on built-in **hide** recapture. Clones computed styles; does not move the live tree.

HTML-in-Canvas is still experimental (Chrome origin trial / `chrome://flags/#canvas-draw-element`). Detection is automatic.

### Custom `capture`

Passing `capture` **turns off both built-in paths**. It is not an extra encoder on top of HTML-in-Canvas.

```ts
capture?: (el: HTMLElement) => Promise<HTMLCanvasElement | HTMLImageElement>
       | { take: typeof capture; clone?: boolean }
```

Constraints:

- **Do not mutate the live tree.** No parking, no `display` toggle, no moving `target` out of document. Capture runs while the user can still see the node; a live-tree rewrite flashes an empty frame.
- If your capturer cannot avoid touching DOM, pass `{ take, clone: true }`. The library clones `target`, hosts the clone offscreen, and calls `take(clone)`.
- Undecoded images, cross-origin bitmaps, and scrollbars are your problem. The library will not wait for `img.decode()` or rewrite CORS.

## Recipes

### 1. Minimum: static node

```js
import { createGenie } from "genie-web";

const genie = createGenie({
  target: "#card",
  origin: "#dock-icon",
  open: false
});

await genie.show();
await genie.hide();
```

Defaults capture for you. Fine for a static card.

### 2. Real window (`<dialog>`, overlay, hide)

Genie hides with `visibility`, not `display`. `visibility: hidden` keeps layout, so the next snapshot can still measure a box. `dialog.close()` / `display: none` collapse the box to 0×0 — put the node back in layout **before** the next `show()`.

```js
const genie = createGenie({
  target: dialog,
  origin: icon,
  open: false,
  zIndex: 3 // below the dock icon, above the desktop
});

async function openWindow() {
  dialog.show();           // must be in layout for capture
  await genie.show();
}

async function closeWindow() {
  await genie.hide({ snapshot: "last" }); // same bitmap as show; target stays hidden
  dialog.close();          // your job, not the library's
}
```

Stacking:

- Overlay default `zIndex` is `2147483000`. If the origin icon should read as “in front of” the funnel, either raise the icon above the overlay or lower `zIndex` (the overlay is `position: fixed` on `document.body`).
- During the warp the real node is `visibility: hidden`. If you keep a second copy visible, you get a double image. If the overlay is under the real window, clicks miss and the mesh is hidden.

### 3. Content that changes between show and hide

There is no automatic cache beyond `"last"`. If the list selection changed and hide should show the **new** preview:

```js
genie.invalidate();
await genie.hide({ snapshot: "fresh" });
```

If hide should look exactly like the frame you opened with (or the window is already tearing down):

```js
await genie.hide({ snapshot: "last" });
```

Warmup is also your job: decode images, finish lazy content, then `show()`. Passing `"last"` without a prior successful capture falls back to `"fresh"`.

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| Flash / empty frame, then the window pops back | `capture` moved or hid the live node. Use `{ clone: true }`, or do not touch the visible tree. HTML-in-Canvas may park `target` during `show()`. |
| Hide looks different from show | Default hide recaptures via SVG, even after an HTML-in-Canvas show. Use `snapshot: "last"`. |
| Overlay under / over the wrong thing | `zIndex` vs a local stacking context. The canvas is on `document.body`; a `z-index` on the icon inside a transformed parent will not beat it. |
| Animation ends and the node is gone | After `hide()`, visibility stays hidden until the next `show()` completes. Pair with `dialog.close()` if you want it closed; call `destroy()` to restore styles. |
| Next `show()` warps a blank / zero-size mesh | Target was `display: none` or `dialog.close()`d at capture time. Show it in layout first, even if still `visibility: hidden`. |
| Custom `html2canvas` and native capture both gone | Expected. Setting `capture` replaces the built-in paths entirely. |

## Vanilla JavaScript

```js
import { createGenie } from "genie-web";

const genie = createGenie({
  target: "#window",
  origin: "#dock-icon",
  duration: 680,
  direction: "auto"
});

await genie.show();
await genie.hide({ snapshot: "last" });
genie.set({ duration: 400, origin: "#other-icon", direction: "bottom" });
genie.invalidate();
genie.destroy();
```

| Method | Description |
| --- | --- |
| `show(opts?)` | Expand from `origin` → `target`. Returns a Promise. |
| `hide(opts?)` | Minimize from `target` → `origin`. Target stays `visibility: hidden` when the promise resolves. |
| `set(config)` | Patch config (including `origin`). Applies on the next `show()` / `hide()`. |
| `invalidate()` | Drop the cached snapshot. Next `"last"` recaptures. |
| `destroy()` | Stop animations, remove the overlay canvas, restore target styles. |

`opts.snapshot` overrides `config.snapshot` for that call only.

## React

Required props: `open`, `origin`. Optional props: `config`, `className`, `style`.

```tsx
import { Genie } from "genie-web/react";

<Genie
  open={open}
  origin={iconRef}
  config={{ duration: 680, direction: "bottom", snapshot: "last" }}
>
  <div className="window">…</div>
</Genie>
```

## Vue

Required props: `open`, `origin`. Optional prop: `config`. Additional attributes (such as `class`, `style`) are automatically forwarded to the wrapper `<div>` container.

```vue
<script setup>
import { Genie } from "genie-web/vue";
</script>

<Genie :open="open" :origin="iconEl" :config="{ duration: 680, direction: 'auto' }">
  <div class="window">…</div>
</Genie>
```

## Svelte

**Action directive** — Required parameters: `open`, `origin`. Optional: any configuration field can be passed directly within the same flat options object.

```svelte
<script>
  import { genie } from "genie-web/svelte";
</script>

<div use:genie={{ open, origin: iconEl, duration: 680, direction: "left" }}>
  …
</div>
```

**Component** — Required props: `open`, `origin`. Optional prop: `config`.

```svelte
<script>
  import Genie from "genie-web/svelte/Genie.svelte";
</script>

<Genie {open} origin={iconEl} config={{ duration: 680, direction: "auto" }}>
  …
</Genie>
```
